# mnist_npu — fe-rtl deliverable README

Stage: fe-rtl | Input: `arch/` (fe-arch output) | Technology: FPGA-generic (Xilinx Artix-7 100T /
Nexys A7 eventual target) — see `spec/spec.md` §2.1 and `arch/arch.md` §2.1 for the documented,
explicit deviation from the pipeline's Sky130 default. No tool was executed by this stage beyond
the mandatory `iverilog` compile-only sanity check (below); the user runs everything else.

## Directory layout

```
rtl/            one module per file (mnist_npu.v is the top; filename == module name + .v)
ip/             empty of vendored sources — IP_PROVENANCE.md documents the one considered-and-
                rejected reuse candidate (uart_tx) and the custom-implementation rationale
filelist.f      every synthesised file (rtl/*.v), no rtl/blackbox/ (none exists — no analog macros)
sdc/            sdc_spec.json — design-facts SDC spec for fe-opensta (this stage does not
                hand-author a .sdc)
doc/            this file
rtl_manifest.yaml
```

No `rtl/blackbox/` directory exists: this design instantiates zero Sky130 (or any) analog macros
(`spec/spec.md` §2, `arch/arch.md` §2.1) — there is nothing to stub.

No `tb/` directory: per the project brief §8, "No testbenches: verification is a separate later
stage (fe-iverilog/fe-cocotb)." This stage's own exit gate is a **compile-only** sanity check
(below), not a functional simulation.

## Memory initialisation mechanism

Every `$readmemh`-initialised ROM/RAM (`weight_rom`, `image_rom`, `label_rom`, `sigmoid_lut`)
defaults its hex-file-path parameter from `rtl/mnist_npu_defs.vh`'s `` `define ``s, all expressed
relative to the `mnist_npu` project root:

| Parameter | Default value |
|---|---|
| `WEIGHTS_HEX_FILE` | `arch/golden_model/weights.hex` (frozen golden package) |
| `IMAGES_HEX_FILE`  | `arch/golden_model/images.hex` (frozen golden package) |
| `LABELS_HEX_FILE`  | `arch/golden_model/labels.hex` (frozen golden package) |
| `LUT_HEX_FILE`     | `rtl/sigmoid_lut.hex` (generated by `tools/gen_sigmoid_lut.py`, this stage — NOT part of the frozen golden package, which holds the *network's* golden vectors, not the LUT table) |

This is why every simulation/synthesis invocation that reads these files must run **from the
`mnist_npu` project root** (matching `arch/golden_model/README.md`'s own convention and the
project brief's exit-check command below). Overriding any of the four for a different environment
is a normal Verilog parameter override at the `mnist_npu` top-level instantiation — no RTL source
edit is needed.

**FPGA bring-up note (out of scope this stage):** Vivado's own `$readmemh` support in behavioural
`initial` blocks generally works for BRAM inference with a resolvable relative/absolute path at
synthesis time; if it does not in practice, the standard fallback is a `.coe`/`.mem` conversion of
the same hex content. This project defers that conversion to the (explicitly out-of-scope) FPGA
bring-up stage.

## Sigmoid LUT generation (REQ-006, non-negotiable bit-exactness)

```
python3 tools/gen_sigmoid_lut.py rtl/sigmoid_lut.hex   # deterministic, already committed
python3 tools/check_lut.py rtl/sigmoid_lut.hex         # MUST print PASS, 0/65536 mismatches
```

Both scripts are pure Python, no floating point, C99-truncating-toward-zero integer division
matching `golden_ref_model.c`'s `sigmoid()` exactly. `check_lut.py` was run during this stage and
printed `PASS` (see `WORKLOG.md`) — this is the fe-rtl-stage evidence required before RTL is
considered complete (project brief §5/§8).

## Pacing parameters — defaults and simulation overrides

All four are plain Verilog `parameter`s on the `mnist_npu` top module, documented in `arch/arch.md`
§4/§8 and restated in each owning module's file header:

| Parameter | Owning module | Default (real hardware) | Simulation override |
|---|---|---|---|
| `HOLD_CYCLES`  | `ctrl_fsm`      | 50,000,000 (~0.5 s @ 100 MHz) | 4-16 |
| `BLINK_CYCLES` | `led_ctrl`      | 5,000,000 (~10 Hz blink)      | 2-4 |
| `CLK_DIV`      | `uart_tx`       | 868 (round(100e6/115200))     | 4 (see arch.md §8 rationale — full 115200 framing accuracy should additionally be checked at least once with the real 868 value) |
| `MAX_LINE_LEN` | `uart_line_fmt` | 80 (longest real line is 69 bytes) | unchanged |

## SDC — fe-opensta authors the `.sdc`, this stage only emits the spec

`sdc/sdc_spec.json` follows fe-opensta's `gen_sdc.py` schema exactly: one clock (`clk_core`, 100
MHz nominal, 10.000 ns period), zero `generated_clocks` (no clock gating anywhere,
`arch/power_plan.md` §2), zero `clock_groups_async` (single clock domain, `arch/cdc_plan.md`),
`inputs`/`outputs` covering `rst_n` and `led[*]`/`uart_tx` per the project brief §8, and **zero**
`false_paths`/`multicycle_paths`. The empty `false_paths` list is deliberate, not an omission: this
design uses a **fully synchronous** reset (`rst_n` sampled like any ordinary synchronous input,
`always @(posedge clk) if (!rst_n) ...`, no async-assert reset synchroniser chain anywhere) — see
`spec/spec.md` §5 and `arch/rtl_coding_guidelines.md` §3 for why. There is therefore no
asynchronous-reset-assertion edge that would need a scoped false path; `rst_n`'s ordinary input
delay constraint (in `inputs[]`) already covers it correctly.

Characterise against `sky130_fd_sc_hd__tt_025C_1v80` (typical) is **not applicable** here — this
project is FPGA-generic, not a Sky130 ASIC flow (see the technology-deviation notes above). A
future FPGA bring-up stage should instead characterise against the target device's own Xilinx
timing corners (out of scope now).

Run (the **user** runs this, not this skill):
```
python3 <fe-opensta>/scripts/gen_sdc.py sdc/sdc_spec.json sdc/mnist_npu.sdc
bash    <fe-opensta>/scripts/qa_sdc.sh  mnist_npu <netlist> sdc/mnist_npu.sdc
```
